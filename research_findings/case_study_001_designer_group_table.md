# Case Study 001: Designer Building AI/ML App with LLMs

## **Case Study Overview**

**Date**: August 2025  
**Source**: Designer's blog post about building Group Table app  
**Topic**: Non-technical user (designer) building complex AI/ML application using LLMs  
**Summary**: A Product Designer with 10+ years experience but no engineering background successfully built and launched an AI/ML app called Group Table in under a year using only LLMs for development.

## **User Profile**

### **Professional Background**
- **Role**: Product Designer (10+ years), former Art Director, Designer
- **Technical Background**: No engineering experience, "too nervous to even open the terminal"
- **Domain Expertise**: Product design, UX, native app design, startup experience
- **Previous Experience**: Silicon Valley startup, worked with ML engineers but couldn't collaborate effectively

### **Setup Context**
- **Setup**: Group Table - AI/ML app for helping groups decide where to eat
- **Motivation**: Wanted to work in AI space, couldn't find engineering partners, decided to go solo
- **Timeline**: August 2023 - August 2024 (1 year)
- **Launch Status**: Successfully launched beta version

## **Setup Details**

### **What They Built**
- **Application Type**: Full-stack AI/ML application with social features
- **Core Functionality**: Group decision-making for restaurant selection
- **Technical Complexity**: AI/ML integration, social features, user management, profile system
- **Platform**: Mobile app (iOS/Android)

### **Development Approach**
- **Primary Tool**: Full LLM (not Cursor or other specialized tools)
- **Supporting Tools**: Terminal, GitHub, standard development tools
- **Methodology**: Iterative development with systematic quality checks
- **Validation**: Friends and family testing, iterative refinement

## **Process Description**

### **Initial Approach**
- **Started with**: Detailed product vision and comprehensive specifications
- **Documentation**: Created detailed specs before any coding began
- **Planning**: Had clear understanding of what they wanted to build
- **Mindset**: "You provide the vision, the LLM provides the code"

### **Iteration Process**
- **Developed**: "Checks and balances" system to keep LLM on track
- **Quality Gates**: Built systematic quality maintenance into the process
- **Documentation**: Maintained comprehensive project documentation throughout
- **Validation**: Tested each iteration with real users

### **Key Decisions Made**
- **Document Everything**: Maintained detailed specifications and process documentation
- **Accept Uncertainty**: Moved forward despite technical limitations
- **Focus on Quality**: Built quality maintenance into the process, not as afterthought
- **User Testing**: Integrated user feedback early and often

## **Outcomes and Results**

### **Final Result**
- **Successfully launched**: Beta version with core functionality
- **Core Value Delivered**: App helps groups decide where to eat
- **User Experience**: Users can evaluate the product effectively
- **Technical Achievement**: Built complex AI/ML app without engineering background

### **Success Metrics**
- **App Launched**: Successfully deployed and accessible to users
- **Core Functionality**: Delivered on primary value proposition
- **User Validation**: Real users can test and provide feedback
- **Technical Quality**: App works as intended

### **Lessons Learned**
1. **Vision + Execution Partnership**: LLMs excel at execution but cannot imagine the product
2. **Documentation is Paramount**: LLMs don't have memory, need explicit documentation
3. **Process Over Perfection**: Accept uncertainty to move forward
4. **Quality Through Iteration**: Build checks and balances, not perfect first attempts
5. **Domain Expertise Matters**: Design background helped with product thinking

## **Key Insights for Elastic-Mob**

### **User Profile Alignment**
This user represents the **ideal elastic-mob user**:
- Someone with domain expertise but limited technical skills
- Using AI to bridge the gap between vision and execution
- Process-oriented and systematic in their approach
- Focused on quality and user experience

### **Process Patterns to Emulate**
1. **Specification-First Development**: Detailed specs before coding
2. **Quality Gate Integration**: Build quality into the process
3. **Documentation Continuity**: Maintain comprehensive project documentation
4. **Iterative Validation**: Test with real users throughout development
5. **Scope Management**: Focus on core functionality before nice-to-have features

### **Failure Patterns to Prevent**
1. **Hallucination Drift**: LLMs making up features to appease users
2. **Memory Loss**: Context not persisting across sessions
3. **Feature Sprawl**: Building non-essential features before core functionality
4. **Quality Compromise**: Accepting poor solutions to move forward

### **Recovery Strategies to Support**
1. **Specification Reset**: Rewrite specs when things go off-track
2. **Quality Gate Implementation**: Build systematic quality processes
3. **Feature Prioritization**: Focus on core value first
4. **User Testing Integration**: Test with real users early and often
